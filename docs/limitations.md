# Limitations

- **Scope.** TypeScript on Node with Vitest and StrykerJS. The demo domain is deliberately small; budgets cap an MR at 5 files, 100 changed lines and 64 mutants per run.
- **A survivor is not a bug.** It shows a behaviour change no test detects. Equivalent mutants (changes no input can observe) exist; the model may label one `equivalent`, which is reported but never changes the score.
- **Arid triage is heuristic.** It removes logging, error-message text and log-only blocks. It can miss other noise and, rarely, hide a mutant on a line that also logs.
- **Draft execution.** AI-drafted tests run in child processes with credentials stripped from the environment, inside the Duo sandbox, after static guardrails (no mocks, no environment, network or dynamic imports). The guardrails are defence in depth, not a sandbox of their own.
- **Same-repository evaluator.** An MR can edit its own CI and evaluator. Changes to protected paths make the gate inconclusive rather than passing, but hostile-repository use needs a policy evaluated from a protected source (for example a compliance pipeline).
- **Role checks in the flow.** The flow's `ai_workflows` token may be refused by GitLab's users and members APIs. Then `apply` fails closed unless GitLab reports this run's own effective permission (the triggering person's composite identity) as Developer or higher and the command is the comment that started the run. Overrides are always verified by the CI gate with its own token.
- **Commit race.** Approved tests are committed to the MR branch with per-file last-commit guards and a head check right before the write. GitLab has no branch-wide compare-and-swap, so a push in the same second could interleave; the next pipeline re-evaluates the gate either way.
- **Token accounting.** GitLab doesn't expose model tokens per flow run. Front Desk reports model calls avoided and mutants avoided, both measured; it does not convert them to tokens, money or carbon.
- **Live status.** See the Status table in the README for what has run on GitLab versus in automated tests. The earlier hash-bound operator CLI (`workflow.ts`) remains for trusted-host use; its live write path was not exercised.
